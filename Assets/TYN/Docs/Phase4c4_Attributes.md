**這不是元素系統，是「思考模式」。** 目標的屬性代表「這個難題吃哪一種腦袋」，
不是「誰打贏誰」。設計新規則時守住這個框架，否則會不小心做成寶可夢。

| ID（程式） | 顯示名 | 顏色 | 值 | 牌框資產 |
|---|---|---|---|---|

## 相剋表

寫在 `Assets/TYN/Core/AttributeChart.asset`。

| 卡 ＼ 目標 | 直覺(紅) | 邏輯(藍) | 批判與創造(綠) | 無(黑白) |
|---|---|---|---|---|
| **直覺(紅)** | **1.0** | **0 ✕** | 0.5 | 1.0 |
| **邏輯(藍)** | **0 ✕** | **1.0** | 0.5 | 1.0 |
| **批判與創造(綠)** | 0.5 | 0.5 | **1.0** | 1.0 |
| **無(黑白)** | 0.5 | 0.5 | 0.5 | 1.0 |

### 設計理由

**直覺 ↔ 邏輯是唯一的互斥對**（快思／慢想 —— 跳躍式直觀 vs 逐步推演）。
批判與創造兩種模式都用，所以站在中間：對誰都不會完全無效，但也很少完美相符。

### 資產裡只有兩條規則

其餘全部從既有行為掉出來，**不要再補規則**：

| 情況 | 從哪來 |
|---|---|
| 同屬性 = `Match` | `GetEffectiveness` 的 `if (card == target) return Match` |
| 目標是「無」= `Match` | `GetEffectiveness` 的 `if (target == None) return Match` |
| 其餘 = `Partial` | `defaultEffectiveness` |
| **「無」當卡片用 = 對誰都 0.5** | 上面兩條的自然結果 —— 萬用但永遠平庸，正是黑白牌該有的定位 |

符合 C19「`None` 應該少用」：16 格裡只有 2 格，且有明確語意依據。

### ⚠️ 平衡上的副作用（尚未處理）

綠因為**永遠沒有 0**，隨機目標下的期望值比紅藍高：

- 紅／藍：`(1.0 + 0 + 0.5) / 3 = 0.50`
- 綠：`(0.5 + 0.5 + 1.0) / 3 = 0.67`

**綠會壓過紅藍。** 建議用資料補平（不用改程式）：綠卡的基礎機率封頂比紅藍低一階
（紅藍有 100%，綠最高 80%），或降低綠卡在牌組裡的比例。

## 手牌變暗（C17）

有了真正的 0% 之後，玩家必須**不 hover 每一張**就看得出哪些是死牌，否則相剋表沒法玩。
所以這是設計的必要配套，不是美化。

`ExploreHandUI` 上新增 `Ineffective Alpha`（預設 `0.35`）。

### 三條不可以改的實作約束

**① 變暗的牌仍然打得出去。** 蓄意失敗是合法策略（C18⑦）—— 打一張死牌會消耗手牌
並讓目標衰減，那是有意義的操作。**變暗是資訊，不是鎖定。**

**② 只調 `CanvasGroup.alpha`，不要碰 `blocksRaycasts` / `interactable`。**
除了上一條，拖曳流程本來就在借用 `blocksRaycasts`（`OnBeginDrag` 會關掉它讓 raycast
穿透自己），兩邊都改會打架。

**③ 不要改用 `image.enabled`。** 停用的 Graphic 收不到任何 raycast 且不報錯，
卡片會變成看得到卻拖不動（HANDOFF §4.4）。

### 對哪個目標算「無效」

相剋只看屬性、與衰減無關，所以只有「目標換了」才需要重算：

- 已選定主要目標 → 對它算
- 沒選定但**場上只有一個目標** → 對那一個算（目前探索的寶箱就是這個情況）
- 多個目標又沒選定 → **不變暗**（「無效」沒有唯一答案，硬壓暗會騙人）

> 最後一條正是 **C18① 主要目標選定在 Phase 6 的實際用途** ——
> 先前判斷它「空轉」是因為當時沒有任何功能需要知道「是對哪個目標」。現在有了。

## 這次改名踩到的坑（會再踩）

### 改名不會幫你改對 `attribute` 的整數值

序列化資料存的是整數。把 `explore_A_60.asset` 改名成 `explore_Insight_60.asset`
**不會**動到裡面的 `attribute: 1` —— 而 `Insight` 是 `3`。

所以那批卡會叫做 Insight、長著綠框、實際上卻是 Intuition，而且**沒有任何錯誤訊息**，
只有相剋結果會靜靜地全錯。

> 改屬性對應時，**檔名、`attribute` 整數、牌框三者要一起改，改完務必交叉驗證**。
> 本次的驗證指令：對每個屬性同時印出 `attribute:` 與 `cardFrameSprite` 的 GUID 比對。

### `.meta` 一定要跟著搬

改名時 `.asset` 與 `.asset.meta` 必須一起搬，GUID 才會保留、引用才不會斷
（`Stage_Explore.prefab` 的起始牌組是用 GUID 引用這 18 張卡的）。
36 個資產超過 HANDOFF §6 的 20 個門檻，**執行前 Unity 必須關閉**。

### Python 在這個專案要設 `PYTHONUTF8=1`

專案路徑含中文，且系統碼頁是 cp950。不設的話輸出中文會直接 `UnicodeEncodeError`
（HANDOFF §5 講的是 MCP，但寫腳本一樣會撞到）。
