## 二、協助者事件、對話事件：跟現在的衝突

1. **沒有「隊伍」與「大廳」。** 大綱的條件全部建立在它上面：
   - 協助者事件：「同行成員不多於 3 人」「某角色未加入大廳」；成功 → 加入隊伍，**本輪結束後加入大廳成為常駐成員**；失敗 → 本輪不再觸發。
   - 對話事件：「某角色在隊伍內」才會觸發。
   - 現在 `CharacterHitbox.activeConditions` 的註解也寫著「協助者／隊伍系統還不存在」。
2. **現在的遭遇節點不看隊伍。** 走到遭遇節點就從 `PDialogueLibrary_Village` 抽《魔術秀》或《有魚》—— 坎貝爾、時藏一開始就會出現。照新大綱，時藏要先在協助者事件裡被招募，《有魚》才會出現。
3. **「事件節點」指哪一種節點不明確。** 大綱說協助者／對話／常駐事件都在「事件節點」觸發。專案裡有三種可能：
   - 地圖上的**遭遇節點**（人物剪影的圖示，現在演機率對話）
   - **探索節點**（進房間前插播事件，現在的常駐事件就是這樣觸發）
   - 首排的**特殊節點**（祭壇）
4. **坎貝爾怎麼進隊伍？** 協助者事件只有時藏、帕克。《魔術秀》要求坎貝爾在隊伍內 —— 他是一開始就在隊伍裡的固定同伴嗎？
5. **判定方式。** 協助者事件寫了成功率（給食物 80% 以上、談判最低），跟現在遭遇節點的「打探索牌提高機率」是同一套嗎？還是固定機率？
6. **帕克沒有角色資料**（立繪、名字），需要美術與文案。

## 三、建議做法（等決定後實作）

- **隊伍與大廳**：`RunContext.party`（這一輪同行的角色 id）＋ `MetaProgressData.lobby`（跨輪保存）。
  - 新條件：`InParty(id)`、`NotInLobby(id)`、`PartySizeAtMost(n)`、`FailedThisRun(id)`
  - 新效果：`JoinParty(id)`；本輪結束時把隊伍成員寫進大廳（`ContributeToMeta`）
- **觸發的地方**（建議）：
  - 遭遇節點 = **協助者事件 ＋ 對話事件**（都是「跟人物互動」，符合節點圖示）
  - 探索節點前插播 = **常駐事件 ＋ 祭壇事件**（維持現狀）
- **協助者事件的判定**：沿用遭遇節點的機率對話（ProbabilityDialogue），大綱的成功率填成各選項的基礎機率；「給吃的」選項需要「身上至少 1 個食物」才能選，選了要挑一個食物交出去。

## 四、這一輪可以先做的（不依賴隊伍系統）

1. 常駐事件規則：可重複、不連續觸發
2. 《米可，要吃飯！》：條件改武器牌 ≥ 10、銷毀 1 張武器牌（從牌組挑）
3. 《任意門》：傳送到沒去過的節點；每張地圖一次
4. 《怪人》：信仰牌 ≥ 2、銷毀 1 張信仰牌 → +60 金幣
5. 《未知的祭壇》：信仰牌 < 2、祈禱給信仰牌、拒絕 +10 SAN
6. 新效果：SAN／HP 加減**固定點數**（大綱寫「恢復 5 點 SAN」「失去 5 點 HP」，現在只有百分比）

2 與 4 需要一個「從牌組挑一張」的畫面 —— 打算沿用卡冊（DeckBook）加一個挑選模式。

## 五、要團隊決定的事

1. 「事件節點」是哪一種節點？（建議：協助者／對話 → 遭遇節點；常駐／祭壇 → 探索前插播）
2. 坎貝爾一開始就在隊伍裡嗎？隊伍上限是「同行成員不多於 3 人」= 含主角 4 人？

4. 《未知的祭壇》要切到祭壇房間（首排那個有手的畫面）還是一般事件畫面就好？給哪一張信仰牌（隨機、還是依區域）？

6. 《任意門》傳送後，玩家是直接進入那個節點的內容，還是只是移動過去、再從那裡選下一步？

## 六、團隊的決定與實作結果（2026-11-02）

決定：協助者／對話事件放**遭遇節點**，常駐／祭壇事件在進探索前插播；坎貝爾測試階段預設在隊伍；協助者成功率可打牌提高；未知的祭壇用有雙手的畫面，先給 ocean；祭壇要不要獨立節點待定；任意門傳送後直接進那一站。

**隊伍系統**
- `RunContext.party`（這一輪）、`MetaProgressData.lobby`（跨輪）。輪次結束時隊伍寫進大廳，下一輪開始就在隊伍裡。
- `GameFlowManager.startingParty` 預設 campbell（測試階段）。
- 條件：`InParty`、`NotInParty`、`NotInLobby`、`PartySizeAtMost`。效果：`JoinParty`。
- 對話庫條目加 `conditions`（抽之前看）與 `neverReplay`（協助者失敗後本輪不再出現，也不算進「全部演過改重播」）。

**遭遇節點的對話**（`PDialogueLibrary_Village`）
| 對話 | 條件 |
|---|---|
| 魔術秀 | 坎貝爾在隊伍 |
| 有···魚···！ | 時藏在隊伍 |
| 協助者：時藏 | 時藏未入大廳、不在隊伍、同行 ≤ 3 |
| 協助者：帕克 | 帕克未入大廳、不在隊伍、同行 ≤ 3 |

**暫定（等文案或企劃）**
- 成功率：大綱只寫時藏「給吃的 80 以上、談判最低」。目前 時藏 80／40／15；帕克 40／50／30 是我抓的。
- 「給他吃的」大綱寫「選擇 1 個食物」，目前判定成功時自動扣 1 個（機率對話沒有挑選介面），判定失敗不扣。
- `<player_name>` 那句先拿掉：遊戲沒有主角名字。
- 帕克只有名字，沒有立繪。
- 每個失敗回答之間 NPC 要說的話，大綱沒寫，用大綱裡現成的台詞（「吃的，給我。」「少煩老子，給我滾！」）。
- 大綱寫「選擇離開或判定失敗」就結束；目前機率對話是答錯一個換下一個，全錯才算失敗。
